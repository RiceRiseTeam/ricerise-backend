# 简易风格文档

## 0. 风格参考

[Go Code Review Comments](https://go.dev/wiki/CodeReviewComments)

## 1. 命名

尽量不使用缩写/单字母变量 除非与导入包名冲突等特殊情况

### 1.1 包名

- 包名应当和文件夹名保持相同
- 包名应当使用名词单数形式

### 1.2 方法名
- 对于单文件包 将单文件看作一个单例使用`func New()` 创建实例
- 对于多文件包 使用 New + 结构名 如 `func NewUserHandler()` 创建实例


## 2. 注释

高复杂度代码必加注释 导出尽量加注释

### 2.1 TODO

- 每次提交都应该保证某一模块在当前语境下是逻辑完备的 对于缺失的没有实现的部分逻辑应当使用`//TODO：`注释
- TODO 格式为 `// TODO(username): something` 描述应当清晰到足够形成完整逻辑

## 3. 错误

### 3.1 错误消息
- 严重Panic 应当使用英文描述错误信息 如果有场景上下文可以在panic 前添加错误日志
- 普通Err 应当尽可能通过日志打印 并且使用中文描述错误信息
